# Privacy & Security

Sythoria Desktop is a Tauri application with a React interface and a Rust backend. It does not add a Sythoria-hosted prompt relay or analytics account. That does **not** mean every workflow is offline: a hosted model, search provider, remote MCP server, cloud transcription endpoint, update check, or network-enabled artifact can receive data when you use it.

## Data-flow summary

| Action                          | Data that can leave the device                                          | Destination                                          | How to avoid it                                                                       |
| ------------------------------- | ----------------------------------------------------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Send to a hosted model          | Prompt, selected conversation context, attachments, provider credential | The configured provider endpoint                     | Use a trusted local Ollama endpoint instead                                           |
| Use web search or fetch         | Query, requested URL, provider credential where configured              | The selected search/fetch service and requested host | Keep the tool disabled                                                                |
| Call remote MCP                 | Tool arguments and server authentication data                           | The configured MCP server                            | Use a local stdio server or disable MCP                                               |
| Cloud transcription             | Recorded audio and service credential                                   | The configured transcription endpoint                | Use a downloaded local Whisper model                                                  |
| Check/download updates          | Version and ordinary HTTP request metadata                              | GitHub/update infrastructure                         | Disable automatic checks if the current version exposes that setting; update manually |
| Load a network-enabled artifact | Requests initiated by approved artifact content                         | Hosts requested by the artifact                      | Keep artifact networking disabled                                                     |

Review the privacy, retention, training, billing, and regional terms of every service you configure. Sythoria cannot change a provider's server-side policy.

## Local storage

The audited v0.4.2 source uses these local mechanisms:

- **API keys and secret values:** stored through the operating system keychain backend.
- **Provider configuration, preferences, projects, and related domain state:** stored in domain-separated AES-256-GCM encrypted files. The master key is held through the operating system keychain.
- **Conversations:** stored as authenticated, content-addressed encrypted snapshots.
- **Exports and files you explicitly save:** stored at the path you choose and protected by that filesystem's permissions.

Encryption at rest does not protect an unlocked user session from malware, a compromised operating-system account, screenshots, clipboard capture, exported plaintext, or a provider that legitimately receives the prompt.

## Network boundary

The WebView communicates with the Rust backend through Tauri IPC. Provider and integration networking is performed by the native backend under Sythoria's endpoint and local-network policy. A restrictive WebView policy does not make a backend request local; the destination configured for the model or tool remains authoritative.

Local-network access should stay disabled unless you intentionally connect to a trusted LAN endpoint. A loopback address such as `127.0.0.1` or `localhost` is narrower than binding a service to every network interface.

## Logs and error messages

The v0.4.2 native log plugin is configured at warning level and targets standard output. The interface also maintains a bounded in-memory log view. The release includes secret-redaction work, but redaction is defense in depth—not permission to publish raw diagnostics.

Before sharing a log or screenshot, remove:

- API keys, tokens, cookies, and authorization headers;
- prompts, model output, audio transcripts, and attachments;
- usernames, local paths, repository remotes, and private hostnames;
- MCP tool arguments and search queries.

## Deletion and backups

Use Sythoria's controls to remove conversations, projects, models, MCP servers, and downloaded voice models. Removing the application alone may not remove operating-system keychain entries or application-data backups. Review the keychain and backup system separately when decommissioning a device.

## Security checklist

1. Install only a release you can trace to the official repository.
2. Keep the operating system and Sythoria updated.
3. Scope provider keys to the least privilege and budget available.
4. Treat MCP servers, terminal commands, repositories, and artifact content as code from their respective authors.
5. Keep local-network access and artifact networking off unless the workflow requires them.
6. Revoke a key at the provider immediately if it may have appeared in a prompt, log, screenshot, repository, or support message.
