# Agentic Tool Loop

Agentic mode allows a model to propose multiple tool calls while working on a registered project. Tool output is returned to the model until the task completes, reaches the configured step limit, or you stop it.

<AgenticLoopDiagram />

## Trust boundary

A model-generated terminal command is still an arbitrary command. It can modify files, start processes, access credentials available to your user account, or send data over the network. Read the command and its working directory before approving it.

Sythoria v0.4.2 adds workspace-boundary and symlink checks to native project tools, but those checks do not make every command harmless. A shell launched inside a workspace can still invoke programs with broader permissions.

## Safer workflow

1. Use a repository with a clean status or create a dedicated branch/worktree.
2. Back up irreplaceable files outside the workspace.
3. Give the task a narrow objective and name the files it may change.
4. Review every command, network call, and file write before approval.
5. Inspect the diff and run project tests before accepting the result.
6. Stop the loop if it requests unrelated credentials, broad filesystem access, or destructive operations.

Check current changes with:

```bash
git status --short
git diff --stat
git diff
```

To discard a single reviewed file, first confirm the exact path, then use:

```bash
git restore -- path/to/file
```

This permanently discards uncommitted changes in that file. Prefer Sythoria's worktree review/apply/discard flow where available, and never use a repository-wide restore command as a generic troubleshooting step.

## Processes and development servers

Run development servers in a visible terminal you can stop and inspect. Do not copy examples that detach an unknown command with `nohup` or shell backgrounding. Confirm the requested port is free, know the process ID, and stop the exact process when the task ends.

## Recovery

If a task behaves unexpectedly:

1. stop the tool loop;
2. do not approve additional cleanup commands;
3. inspect `git status`, the worktree, and running processes;
4. preserve useful logs after removing secrets; and
5. restore only reviewed paths from a known commit or backup.
