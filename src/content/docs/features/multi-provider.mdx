# Multi-Provider Chat

## Direct Request Architecture

Sythoria Desktop executes all AI provider interactions directly from your machine without any intermediary proxy servers:

1. **Run Context Assembly**: When a message is sent, Sythoria builds an immutable run context combining your active model choice, system prompt, temperature, and attached tools or workspace instructions.
2. **OS Keychain Secret Retrieval**: Provider API keys are fetched directly from your operating system's native credential vault (macOS Keychain, Windows Credential Manager, Linux Secret Service) into local memory for the request.
3. **Direct Provider Connection**: Sythoria establishes a direct, encrypted HTTPS / Server-Sent Events (SSE) stream straight to the selected provider's endpoint (OpenAI, Anthropic, Gemini, NVIDIA NIM, OpenRouter, or local Ollama).
4. **Zero Middleman Proxying**: Request payloads, API tokens, and streaming responses flow exclusively between your local desktop client and the target provider. Sythoria operates completely stateless with no intermediate servers or telemetry logging.

## Add another provider

1. Open **Settings** and choose **Add Model**.
2. Select a preset or **Custom**.
3. Verify the API base, model ID, and API format.
4. Add the provider key if the endpoint requires one.
5. Save and run the connection check.
6. Send a short test message before adding private context.

Provider keys are stored through the operating system keychain. Non-secret provider configuration is stored in domain-separated AES-256-GCM local files.

## Switch during a conversation

Changing the model affects the next request. The provider can receive the conversation context Sythoria includes with that request, including earlier messages produced by another provider. Start a new conversation when context should not cross provider boundaries.

Pricing, context windows, rate limits, safety handling, retention, and output behavior remain provider-specific. Sythoria does not guarantee a cost reduction when you switch models.

## Custom endpoints

For an OpenAI-compatible endpoint, enter the complete chat-completions URL expected by that server. Prefer HTTPS with a valid certificate for any non-loopback host. Do not send a production key to an endpoint you do not control or trust.

Enabling local-network access broadens which private addresses the backend may contact. Enable it only for a specific trusted endpoint and protect remote services with firewall rules, authentication, and TLS.
