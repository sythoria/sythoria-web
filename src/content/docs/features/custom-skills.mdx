# Reusable Custom Skills

A skill is a local instruction package that can be attached to a conversation or project. It can define conventions, workflow steps, and tool guidance without pasting the same text into every prompt.

## What a skill can and cannot do

A skill changes model context. It does not make a model or tool faster, grant permissions, or make unsafe commands trustworthy. Longer skill text also consumes context and can affect cost for hosted models.

## Create a skill

1. Open the Skills area in Sythoria.
2. Create a skill with a clear name and one bounded purpose.
3. State prerequisites, allowed tools/paths, expected output, and stop conditions.
4. Save it and attach it to a disposable test conversation.
5. Review tool proposals and output before using it in a real project.

Example instruction body:

```markdown
# Review a TypeScript change

- Read the changed files and nearby tests.
- Do not modify files outside the named package.
- Report correctness and accessibility issues with file/line evidence.
- Run the package's existing test command after approved edits.
```

## Portability and backup

Treat internal storage locations and cache formats as implementation details unless the application exposes a documented export. Use Sythoria's export/import controls where available and keep the original skill text in a versioned, non-secret location.

Never put API keys, personal tokens, private certificates, or production credentials in a skill. The skill can be sent to the active model as context.
