# OpenRouter

OpenRouter routes requests to model providers under its own account, routing, logging, retention, and billing settings. This adds another service boundary beyond Sythoria and the eventual inference provider.

## Configure Sythoria

1. Create a key at [openrouter.ai/keys](https://openrouter.ai/keys).
2. Review OpenRouter privacy and provider-routing controls.
3. In Sythoria, open **Settings**, add a model, and select **OpenRouter**.
4. Confirm the preset, paste the key, save, and run the connection check.

| Setting       | Desktop v0.4.2 value                            |
| ------------- | ----------------------------------------------- |
| API base      | `https://openrouter.ai/api/v1/chat/completions` |
| Default model | `anthropic/claude-sonnet-5`                     |
| API format    | OpenAI-compatible chat completions              |

The preset ID can become unavailable. Copy an exact current route from the [OpenRouter model catalog](https://openrouter.ai/models). The catalog is the source for current providers, prices, context, availability, and modality.

## Routing and privacy

Automatic fallback can send the same request to a different underlying provider. Configure provider preferences and data-policy filters in OpenRouter before using sensitive content. A “free” or cheaper route can have different logging, rate limits, uptime, and data terms.

## Troubleshooting

| Status | Check                                        |
| ------ | -------------------------------------------- |
| 401    | OpenRouter key and account                   |
| 402    | OpenRouter credit balance                    |
| 403    | Route/provider terms or account restrictions |
| 404    | Exact `provider/model` identifier            |
| 429    | OpenRouter or upstream provider limits       |

Revoke an exposed key at OpenRouter; removing it only from Sythoria does not invalidate it.
